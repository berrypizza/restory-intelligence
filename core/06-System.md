# About

Manifesto는 왜 존재하는가를 정의한다.

Principles는 어떻게 판단하는가를 정의한다.

Brand는 세상을 어떻게 바라보는가를 정의한다.

Language는 어떻게 말하는가를 정의한다.

Customer는 사람이 왜 행동하는가를 정의한다.

Content는 현장을 어떻게 자산으로 바꾸는가를 정의한다.

System은

그 모든 것을 반복 가능한 구조로 만드는 방법을 정의한다.

RESTORY는

잘하는 사람에게 의존하는 회사가 아니라

좋은 시스템으로 반복되는 회사를 만든다.

---

# System Philosophy

좋은 결과는

우연히 나오면 안 된다.

좋은 결과는

반복 가능해야 한다.

RESTORY의 모든 작업,

모든 콘텐츠,

모든 상담,

모든 기록은

다음 사람이 다시 따라 할 수 있어야 한다.

기억하지 않는다.

문서화한다.

감으로 하지 않는다.

구조로 만든다.

---

# System Formula

RESTORY의 모든 시스템은

아래 순서를 따른다.

Reality

↓

Record

↓

Structure

↓

Repeat

↓

Improve

---

## Reality

실제 현장.

실제 고객.

실제 원인.

실제 작업.

---

## Record

사진,

고객 말,

원인,

해결 방법,

결과를 기록한다.

---

## Structure

기록을

문서,

템플릿,

라이브러리,

에이전트로 정리한다.

---

## Repeat

같은 품질이

다시 나오도록 만든다.

---

## Improve

실제 결과를 보고

문서를 업데이트한다.

---

# RESTORY Operating Layers

RESTORY 시스템은

다섯 개의 층으로 움직인다.

---

## 1. Core

변하지 않는 기준.

- Manifesto
- Principles
- Brand
- Language
- Customer
- Content
- System

Core는

모든 문서보다 우선한다.

---

## 2. Services

서비스별 지식.

- Upper Cabinet
- Cabinet Door
- Chair
- Sofa

Services는

현장의 원인,

고객 심리,

검색 의도,

사진 기준,

FAQ를 담는다.

---

## 3. Agents

AI 직원의 업무 방식.

- Case Agent
- Blog Agent
- Shorts Agent
- SEO Agent
- Consult Agent

Agents는

입력,

사고 순서,

검증,

출력 형식을 정의한다.

---

## 4. Library

계속 쌓이는 자산.

- Hooks
- Titles
- CTA
- Customer Words
- Psychology
- FAQ
- Visual

Library는

실제 현장과 콘텐츠에서 나온 데이터를 저장한다.

---

## 5. Templates

출력 양식.

- Case
- Blog
- Shorts
- SEO
- Prompt

Templates는

형식을 통일한다.

---

# System Rule 01

## 현장이 먼저다.

모든 시스템은

현장에서 시작한다.

AI가 먼저가 아니다.

문서가 먼저도 아니다.

실제 고객,

실제 원인,

실제 사진,

실제 결과가 먼저다.

---

# System Rule 02

## 한 번 만든 것은 다시 쓰이게 만든다.

현장 하나는

한 번 쓰고 끝나면 안 된다.

하나의 현장은

CASE,

블로그,

쇼츠,

홈페이지,

FAQ,

상담 문장,

라이브러리로 확장되어야 한다.

---

# System Rule 03

## 반복되는 것은 문서화한다.

두 번 이상 반복되는 작업은

문서로 만든다.

세 번 이상 반복되는 질문은

FAQ로 만든다.

다섯 번 이상 반복되는 훅은

Library에 넣는다.

---

# System Rule 04

## 문서는 살아 있어야 한다.

문서는 완성물이 아니다.

운영하면서 계속 바뀐다.

더 좋은 표현이 나오면 수정한다.

새로운 고객 말이 나오면 추가한다.

더 나은 기준이 생기면 업데이트한다.

---

# System Rule 05

## AI는 문서를 따라야 한다.

AI는 자유롭게 쓰는 도구가 아니다.

RESTORY의 AI는

Core를 읽고,

Service를 이해하고,

Agent의 순서를 따르고,

Template 형식으로 출력해야 한다.

---

# System Rule 06

## 모든 결과는 다시 시스템으로 돌아온다.

콘텐츠를 만들고 끝내지 않는다.

결과를 본다.

조회수,

저장,

문의,

댓글,

검색 유입,

상담 전환을 확인한다.

그리고

잘된 이유와

안 된 이유를

Library와 Agent에 반영한다.

# Commit Rule

Git commit은

가능하면 아래 형식을 따른다.

```bash
docs: add System core document
docs: update Customer language
agent: add Case Agent
service: add Upper Cabinet knowledge
library: add customer words
refactor: improve Content structure
```

커밋은

나중에 왜 바뀌었는지 알 수 있어야 한다.

---

# Update Rule

문서를 수정할 때는

항상 세 가지를 남긴다.

1. 무엇을 바꿨는가
2. 왜 바꿨는가
3. 어떤 문서에 영향을 주는가

문서가 많아질수록

변경 기록은 브랜드의 기억이 된다.

---

# System Checklist

새 문서를 만들기 전에 확인한다.

- Core 철학과 충돌하지 않는가?
- 실제 현장에 기반하는가?
- AI 없이도 사람이 이해할 수 있는가?
- 반복 가능한 구조인가?
- 나중에 업데이트하기 쉬운가?
- 다른 문서와 연결되는가?
- RESTORY다운가?

하나라도 NO라면

다시 설계한다.

---

# Final Principle

RESTORY는

프롬프트를 모으는 회사가 아니다.

RESTORY는

현장을 기록하고,

기록을 구조화하고,

구조를 반복하고,

반복을 개선하는 브랜드다.

좋은 시스템은

좋은 사람보다 오래간다.

그리고

좋은 시스템은

더 좋은 선택을 반복해서 만든다.
